     Plan: Make DuckDuckGo search actually work in the HTTP backend

     Context

     The pipeline's only search source is DuckDuckGo, and today every company
     comes back
     not_found (0.0) with "Search failed to return results." I diagnosed the
     true cause by
     probing DDG directly from this container:

     - The network is fine — TCP + TLS to html.duckduckgo.com complete, general
     egress works.
     - The current HttpBackend.search() (scripts/check_certifications.py:200)
     does a GET to
     https://html.duckduckgo.com/html/?q=... with only User-Agent: Mozilla/5.0.
     DDG's anti-bot
     system flags that as automated traffic and returns its "anomaly / 
     challenge" page (HTTP
     202, or 200 with zero results). The parser then finds 0 links → not_found 
     (0.0) for everyone.

     Key discovery — DDG works from here with the right request shape.
     Empirically, a POST to
     https://html.duckduckgo.com/html/ with a real browser User-Agent plus
     Referer and
     Origin headers returns HTTP 200 with 10 real results. Verified live:

     ┌───────────────────────────────┬─────────────────────────────────────────┐
     │         Request shape         │                 Result                  │
     ├───────────────────────────────┼─────────────────────────────────────────┤
     │ GET + Mozilla/5.0 (current    │ 200, 0 results (anomaly page)           │
     │ code)                         │                                         │
     ├───────────────────────────────┼─────────────────────────────────────────┤
     │ GET + real browser UA         │ 202, 0 results                          │
     ├───────────────────────────────┼─────────────────────────────────────────┤
     │ POST + real UA, no            │ 202, 0 results                          │
     │ Referer/Origin                │                                         │
     ├───────────────────────────────┼─────────────────────────────────────────┤
     │ POST + real UA + Referer +    │ 200, 10 results (Bosch, Toyota, Nestle  │
     │ Origin                        │ each 10)                                │
     └───────────────────────────────┴─────────────────────────────────────────┘

     Second discovery — DDG rate-limits per IP. After ~15 rapid requests, DDG
     soft-blocks the IP
     and returns 202 for everything (fresh queries, cookies, 90s cooldown all
     still 202). So the fix
     is two parts: (1) the correct request shape, and (2) pacing + long backoff
     so a 193-company run
     doesn't trip the throttle. The existing _parse() needs no change — it still
     matches result__a
     anchors in the 200 response.

     Approach

     All changes are in scripts/check_certifications.py, confined to the HTTP
     backend plumbing.

     1. Add a realistic request identity (module level, near line 75)

     BROWSER_UA = ("Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36
     "
                   "(KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36")
     DDG_HTML = "https://html.duckduckgo.com/html/"

     2. Rewrite HttpBackend.search() to POST with browser headers 
     (scripts/check_certifications.py:200)

     - Use urllib.request.Request(DDG_HTML, data=urllib.parse.urlencode({"q": 
     query}).encode(), ...)
     so it's a POST with a form body (not a query-string GET).
     - Headers: User-Agent: BROWSER_UA, Referer: https://html.duckduckgo.com/,
     Origin: https://html.duckduckgo.com, Content-Type: 
     application/x-www-form-urlencoded,
     plus a normal Accept / Accept-Language.
     - Reuse a module-level opener with a cookie jar
     (urllib.request.build_opener(urllib.request.HTTPCookieProcessor(http.cookie
     jar.CookieJar())))
     so cookies from the first call carry forward (mimics a browser session).
     Add import http.cookiejar.

     3. Detect the anomaly/throttle response and back off (new helper 
     _ddg_search_raw)

     - Treat HTTP 202, or a 200 whose parsed result count is 0 and whose body
     contains the
     anomaly markers ("anomaly"/"challenge"), as throttled — not "no results."
     - On throttle, retry with exponential backoff (e.g. 20s → 45s → 90s,
